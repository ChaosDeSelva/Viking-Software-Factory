Sindri setup guide

Versioned specifications, dependency plans, human approvals and evidence based delivery reviews.

Before you begin

Sindri owns specifications, plans and delivery decisions. Mimir runs the agents and Brokkr defines verification. Sindri does not automatically merge or deploy the result.

Requirements

Node.js 25 or newer, pnpm and Git 2.38 or newer.

Get the source

git clone https://github.com/ChaosDeSelva/Sindri.git
cd Sindri

Build and run

pnpm install --frozen-lockfile
pnpm build
node apps/cli/dist/main.js init
node apps/cli/dist/main.js doctor
node apps/cli/dist/main.js start

Run these commands from the repository root. Keep local state and credentials outside version control.

Complete READMERelease notes

Your first session

  1. Initialize the local configuration, run doctor and start the service. Configure Mimir before submitting a plan for execution.
  2. Register a project and capture a small request. Draft a specification, inspect its assumptions and approve the revision you want to build.
  3. Review the task plan and approve it separately. Start the approved plan from Heimdall or the documented API.
  4. Inspect verification artifacts and the independent review. Export a local delivery or proposed PR text; GitHub is optional.

Operating boundaries

Delivery depends on the configured execution runtime and reviewer. A passing example is not a guarantee for arbitrary projects. External tracker credentials and agent logins are configured separately. Manual accessibility acceptance remains pending.
