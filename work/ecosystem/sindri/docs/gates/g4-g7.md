## Full factory acceptance run (G6)

Command, from the repository root (needs a built Mimir checkout next to this repo: `cd ../mimir && pnpm build`):

```sh
pnpm test:acceptance
```

`apps/server/test/acceptance/factory-run.test.ts` starts Mimir as a child process (`node ../mimir/apps/server/dist/main.js`, `MIMIR_RUNTIME=fake`, a temp `MIMIR_DATA_DIR`, `MIMIR_PORT=0`, a generated `MIMIR_AUTH_TOKEN`, `MIMIR_TICK_MS=100`). No Mimir source is imported. Sindri runs in process with the `FakeProvider` director (the demo spec plus a backend criterion) over a temp SQLite file. When no Mimir build is found the test is skipped with the reason ``no Mimir build found (build ../mimir with `pnpm build`)``. It is not part of `pnpm check` (it takes one to three minutes and depends on the sibling repo).

## Recovery integration validation (2026-10-14)

The integrated run uses the local Mimir SDK/protocol 0.2.0 (wire protocol 1) and Brokkr 0.1.0 releases. It passes ticket import, spec/plan approval, six crews, restart recovery, fail then pass retry, all six quality gates, PR approval, delivery trace, and 29 sourced knowledge proposals.

The assertions require an actual verified execution, complete test and diff evidence, all gates passing, and a delivered report before knowledge generation. PR requests remain pending until the corresponding Mimir approval has been consumed. The test does not create a remote pull request.

This acceptance run uses a fake director and fake runtime. A clearly marked fixture supplies review artifacts and dependency directories; real Brokkr checks run against each task's selected lock. The planted test failure is one shot and does not prove agent repair. A separate local live test uses HerdR to run the logged in Codex CLI, repairs an arithmetic implementation without modifying tests, and passes Mimir's independent Brokkr verification.

Harness selection is persisted with each plan task and forwarded to Mimir as an immutable verification lock. Knowledge proposals are exposed by delivery routes and the Knowledge screen; generation and acceptance/rejection require the approval factor.

## G7: release hardening (partial)

* `pnpm release:local` builds, packs, checks licences, writes the SBOM and bundles `dist/sindri-<version>-<os>-<arch>.tar.gz`; `scripts/install-local.sh` installs it to `~/.local/share/sindri` with a `~/.local/bin/sindri` shim. `pnpm test:release` extracts, installs into temp dirs and runs `sindri doctor` from the installed copy.
* `sindri doctor` checks Node, git, the data dir, `config.json`, the provider key (presence only) and Mimir protocol compatibility through `GET /v1/capabilities` (`docs/compatibility.md`).
