# Licenses

Mimir is Apache-2.0 (`LICENSE`). Dependencies must be Apache-2.0 compatible; copyleft and
source-available licenses are avoided (ecosystem rule 2).

## Ruling: MPL-2.0 development-only dependencies

Ruled 2026-10-14 (ledger: `.sdd/progress.md`, task S7a): MPL-2.0 dependencies are acceptable
when they are used only for development and testing and are not redistributed.

| Package | License | Where | Why it is allowed |
|---|---|---|---|
| `axe-core` | MPL-2.0 | `apps/web` devDependency | Accessibility checks in the Playwright e2e suite only. |
| `@axe-core/playwright` | MPL-2.0 | `apps/web` devDependency | Same. |
| `lightningcss` (and the platform package `lightningcss-darwin-arm64`) | MPL-2.0 | Transitive dev dependency of `vite` (CSS minification) and `@tailwindcss/node` (via `@tailwindcss/vite` in `apps/web`) | Build-time CSS transform only, in the web build and in vitest. Its code is not part of the built `apps/web/dist` output and is not imported by any shipped server or CLI code. |

They are not imported by any shipped code. `pnpm release:local` builds the runtime bundle with
`pnpm deploy --prod`, which excludes devDependencies, so none of these packages is in the release
tarball or in the `@mimir/protocol` and `@mimir/sdk` tarballs. MPL-2.0 is file-level copyleft; we do not
modify these packages. If this ever changes (for example bundling an accessibility checker into the
product, or shipping a server-side CSS pipeline), swap the package for a permissively licensed one
first.

## Enforced policy

`pnpm licenses:check` (`scripts/licenses.mjs`) fails on anything outside: Apache-2.0, MIT, MIT-0, BSD-2-Clause,
BSD-3-Clause, ISC, 0BSD, Unlicense, CC0-1.0, BlueOak-1.0.0, Python-2.0, Zlib. MPL-2.0 passes only when no
production dependency chain reaches the package. Unknown or missing licenses fail. MIT-0 is added to the
requested list because it is strictly more permissive than MIT (two transitive packages use it). The generated
tables at the bottom of this file are rewritten by that command.
