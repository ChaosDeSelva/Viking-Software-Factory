Mimir setup guide

Crews, scheduling, execution controls and durable event history.

Before you begin

Mimir owns missions, crews, execution and runtime observations. Sindri can submit approved plans; Brokkr supplies verification; Heimdall presents the operator controls.

Requirements

Node.js 25 or newer, pnpm 12 and Git.

Get the source

git clone https://github.com/ChaosDeSelva/Mimir.git
cd Mimir

Build and run

pnpm install --frozen-lockfile
pnpm build
node apps/cli/dist/main.js init
node apps/cli/dist/main.js doctor
node apps/server/dist/main.js

Run these commands from the repository root. Keep local state and credentials outside version control.

Complete READMERelease notes

Your first session

  1. Initialize Mimir and run doctor before starting the server. The default fake runtime is useful for exploring the API without invoking a model.
  2. The API listens on http://127.0.0.1:7700. Use the generated bearer token for authenticated requests. The server does not serve the web UI; use Heimdall or the development web app.
  3. For real work, install and authenticate Codex or Claude Code, select the runtime described in the runtime guide, and register a disposable Git repository first.
  4. Follow the mission, task and verification events. Review approvals and evidence before accepting or merging changes.

Operating boundaries

Codex and Claude Code are the primary local harnesses. Other agent profiles and Zellij, cmux and Orca bridges remain experimental without authenticated live acceptance. Local agents run with your user privileges. Manual accessibility acceptance remains pending.
