Skidbladnir setup guide

Disposable development workers, local simulation and an optional owned AWS fleet.

Before you begin

Skidbladnir owns disposable worker infrastructure. Mimir owns agent execution placed on that infrastructure. The local simulator is the default and does not launch real virtual machines.

Requirements

Node.js 24 or newer and npm. The default simulator needs no AWS account.

Get the source

git clone https://github.com/ChaosDeSelva/Skidbladnir.git
cd Skidbladnir

Build and run

npm ci
npm run build
npm test
npm start

Run these commands from the repository root. Keep local state and credentials outside version control.

Complete READMERelease notes

Your first session

  1. Build and start the application, then open http://127.0.0.1:4380. The default simulator needs no AWS account.
  2. Create a simulated worker, inspect its events and exercise stop, start and terminate. Termination retains the history.
  3. For actual compute, follow the AWS guide and choose an explicit profile, region and isolated fleet. AWS usage can incur charges.
  4. Verify expiration and teardown in your own disposable environment before running meaningful workloads. Keep credentials and runtime state out of Git.

Operating boundaries

Local simulation expiration only runs while the API is active and reconciles afterward. AWS expiration is configured independently. SSM reconnect starts a fresh shell; artifacts and mission envelopes are bounded. New images and account configurations need their own acceptance run.
