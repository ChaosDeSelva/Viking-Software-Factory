Viking Software Factory setup guide

Independent local tools for planning, execution, verification and delivery.

Install the Mac preview

Download the v0.2.0 setup ZIP. Extract it, move Viking Factory.app to Applications and open it. Select optional components, choose Install bundle and select factory-manifest.json from the extracted bundle directory. Run Health check, sign into your agent tools and start the factory. Node and npm are included; Git and agent CLIs are separate prerequisites. Preview updates checks for compatible signed releases. No cloud resources are created by installation.

Before you begin

The factory combines independent local tools. It does not require GitHub to run, and publishing code is separate from accepting a local delivery. Bifrost connects agents to Hulder; Skidbladnir manages optional disposable compute.

Requirements

Node.js 25 or newer, pnpm 12.11.2, Git and installed agent CLIs. Agent login is separate.

Get the source

git clone https://github.com/ChaosDeSelva/Viking-Software-Factory.git
cd Viking-Software-Factory

Build and run

./build.sh
node outputs/local-factory/factory.mjs

Run these commands from the repository root. Keep local state and credentials outside version control.

Complete READMERelease notes

Your first session

  1. Build this collection with Node.js 25 or newer and pnpm 12.11.2. Install and authenticate the agent CLIs you intend to use.
  2. Start the local launcher and keep its terminal open. Open Heimdall at http://127.0.0.1:4320 using the credentials printed locally.
  3. Create a disposable project and a tiny request, such as a counter. Review the specification and plan, then start the approved execution.
  4. Inspect the resulting worktree, verification report and independent delivery review. Accept or export the work only after reviewing the evidence. Stop the launcher with Control C.

Operating boundaries

Codex and Claude Code are the primary local agent paths. Other vendor profiles and terminal bridges without authenticated acceptance remain experimental. Manual screen reader acceptance remains pending. Remote and AWS acceptance cover specific disposable environments, not every host or image.
